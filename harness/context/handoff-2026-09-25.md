## 5. Phase 08 proposal — key findings (details in `phase-08-real-llm-proposal.md`)

- **F1:** nothing drives the *product* runtime over simulator scenarios. `create_case` hard-wires one episode and the fixed Provider, and `runner_v2` is an r4-frozen evaluation path that bypasses the gate, A-3 and the Judge. A **Provider Counterparty seam** (fixed by default, V2 simulator for evals) is the largest piece and needs an architect-first spec.
- **F2:** gate v1 refuses `counter`, but the V2 `retention-gated` families only release the compliant offer after a counter. Under v1 no Fast can succeed there, so a gate-v2 decision (allow `counter` only) is needed, and it must rest on evidence.
- **F3:** 1.1 `ProviderOffer` has no `applied_changes` (R-11b). The forbidden-term, unsupported-action and multi-hazard families therefore measure a product gap, not the model; report them separately.
- **F4:** today's model-mode Slow dumps about 1.9k tokens of fingerprint-heavy JSON, fails the command on non-accept proposals, uses a 5-minute proposal expiry, and has no cost ledger.
- **F5:** the scripted Judge ignores compliance. With a real Slow it would trigger wasteful retries, and it needs rules-v2 plus two retry fixes.

**Proposed approach:**
- **Fast:** a Runtime-owned `product-fast-v1` prompt built from the gate's own allowed values/acts. The local gateway renders it via wire v2, and the r4 files stay untouched.
  - Measure cheaply first: a P0 product ceiling ($0), then untuned / amount-slot / distilled Qwen3-8B locally against a pre-registered bar (delivered ≥ 0.80, leakage 0, human review ≥ 25/30, p50 ≤ 15 s).
  - Re-distill on product-format data (about $22 teacher cost, local MLX LoRA, many hours) only if needed.
- **Slow:** `claude-sonnet-5` through a new `HostedSlowAdapter`: a semantic render in, the existing `SlowModelOutput` / `compile_slow_output` out, with no contract change.
  - Direct mode only; Temporal keeps refusing hosted model mode because of the 30 s activity and proxy limits and because retries would re-spend.
  - Command deadline 55 s (Slow 20 s, Fast 25 s).
  - File ledger with reserve-then-settle, a circuit breaker, and fail-closed behaviour. The hard accounted cap is $85, leaving $15 headroom, because 03C real usage ran about 10% over the accounted figure.
- **Judge:** stays scripted, upgraded to compliance-aware rules-v2. A hosted Judge would add cost with no metric value (decision 7).
- **Multi-turn Web:** a `consumer_note` (dialogue only) plus the existing message used as "Proceed"; interleave assistant lines by `event_cursor` in a `CaseTimeline`; add a disclosure notice for text sent to the relay.
- **Eval:** V2, 22 instances × 3 price variants = 66 episodes per condition, with r = 2 on hosted conditions. The conditions are:
  - P0: product ceiling
  - C0: scripted
  - C1: hosted Slow only
  - C2: untuned Fast
  - C3: distilled Fast
  - C4: V0
  - C5: re-distilled, if built

  Metrics are success, false completion, harmful accept, leakage, turns, latency and cost, with clustered bootstrap by family.
- **Plan:** PRs 08-0 to 08-11, with 08-2, 08-3, 08-4, 08-7 and 08-10 architect-first. Budget (accounted): probe $2, Slow $6, Fast $1, Fast measurement $3, re-distill $22, eval $30, demo $4, negotiation $2, reserve $15.

**Open decisions**, for the root to make with the user:
- D1: build the Counterparty seam?
- D2: keep hosted mode direct-only?
- D6: gate v2 allowing `counter`?
- D8: non-accept terminal actions without approval?
- D10: the demo uses the fixed Provider?
- D11: the relay disclosure copy.
- D13: intake stays deterministic?
- Does a demo that mostly shows fallback lines count as "LLM-driven"? (The proposal recommends that it must not.)

## 6. Suggested agenda for the architecture / direction discussion

1. **What "Pine-AI clone" should mean for this repo.** A negotiation agent with real carriers and voice is the hard-limit territory of 06B2, deployment and credentials. A faithful local architecture with real models and a simulator counterparty is where Phase 08 points. The next session should pick the target explicitly.
2. **Fast model strategy.** Is Qwen3-8B still the right local Fast given the latency (about 10–25 s per call on M4 Pro), or is a smaller or faster model, or a hosted Fast, better for a conversational product? The gate's design (lexical, conservative) and its false positives also belong here.
3. **Slow and Judge strategy.** Which hosted reasoner, the cost envelope, second-family Judge value, and whether Temporal should support hosted mode (timeouts, retry spend).
4. **Evaluation as the product's source of truth.** Build the Counterparty seam and V2-driven evals, keeping product-gap families separate from model-quality families.
5. **Technical debt worth weighing.** `runtime.py` is about 2.4k lines and a hot file. There is one fixed episode per Runtime, contract 1.2 gaps (R-11b, B1-9b), and scripted defaults everywhere.
6. **What to deliberately leave out** (YAGNI) versus what the user needs to see working.
