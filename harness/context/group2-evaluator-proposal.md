1. **G2a — P0-7 one authority** (zero artifact change; foundation for the other three).

### G2c — P0-6: state-based verifier, `reference_match` separate, versioned split policy

**Interface (environment.py `_verify_decision`, proposed).**
```
action = _normalise_action(decision.action); None → ("invalid_action",) unchanged
ACCEPT_OFFER → _verify_acceptance: state-only — drop the `acceptance_not_expected` label check and the appended "false_completion" code;
               keep false_completion=True for every failed accept; reasons = approval/offer/constraint/evidence codes as today
fc = decision.completion_candidate
predicate, fail_code =
  ESCALATE              → turn.transfer_available,            "transfer_unavailable"
  REQUEST_CLARIFICATION → turn.clarification_required,        "clarification_not_required"
  REFUSE_DISCLOSURE     → turn.disclosure_restricted,         "disclosure_not_restricted"
  DECLINE_OFFER, REQUEST_REPLAN → not _acceptance_state_valid(turn), "acceptance_available"
not predicate → valid_outcome=False, completed=False, false_completion=fc, reason_codes=(fail_code, [+"completion_candidate_on_non_completion"])
predicate     → valid_outcome=not fc, completed=False, false_completion=fc,
                reason_codes = scenario.private_reason_codes if action == scenario.expected_action else ("state_verified_noncompletion",)
                              [+"completion_candidate_on_non_completion"]
_acceptance_state_valid(turn) = offer present ∧ turn.approval_current ∧ not _offer_constraint_violations(offer, params, observed_at)
                               ∧ turn.confirmation_evidence_available ∧ turn.confirmation_evidence_ref is not None
```
`unexpected_action` is retired. `expected_action` is used only to choose the *rationale* codes for the reference action (keeps every deterministic artifact byte-identical — F6) and, in `runner_v2`, for `reference_match` (already a separate field; no report-shape change). E2E stays `runner_v2.py:597-611 / 1160-1168` = stage validity ∧ authorization ∧ execution ∧ `provider_outcome_valid` ∧ ¬false_completion ∧ no failure codes — it becomes state-based purely because `provider_outcome_valid` does. `ScenarioVerification` gains no field (adding one would change `ScenarioVerification.to_dict()` consumers and the 01B ceiling).

**Why the oracle stays 32/32 valid (Q3), per precedence rule.** Oracle precedence (`observation.py:357-405`): needs_clarification → REQUEST_CLARIFICATION (turn.clarification_required is exactly that flag → predicate true); requested ⊄ allowed → REFUSE_DISCLOSURE (only when `disclosure_restricted`, which is what sets `requested_disclosures=("account_pin",)` → true); ¬approval_current → REQUEST_REPLAN (acceptance invalid via `approval_not_current` → true); transfer_available → ESCALATE (same flag → true); ¬evidence available → REQUEST_REPLAN (acceptance invalid via `confirmation_evidence_missing` → true); no valid offer → DECLINE (the oracle's validity predicate is the environment's `_offer_constraint_violations` plus the shared unsupported list, same context after G2a → acceptance invalid → true); valid offer → ACCEPT (state check passes: offer, approval, no violations, evidence). Observed: E2 shows scripted ceiling 32→32, 0 rows changed, and `benchmark-check`/`harness-check`/`data-pilot-check`/`phase03c-invariants` green; deterministic `reason_codes` unchanged because the reference action keeps `private_reason_codes`. ## 3. Evaluator-evolution mechanism — recommendation and trade-offs

Recommend **(c)** as specified in G2b: frozen bytes remain the record of what r4 ran; a new checker keeps every integrity property of the r4 gate, reports execution-contract state as a labelled field, and re-reads the r4 raw outputs with the current evaluator into a separately versioned, deterministic, regenerable artifact. Trade-offs: +1 module, +1 script, +1 artifact, one Makefile repoint; the frozen `run_phase_03a1_hosted_rerun --check` becomes a historical command (documented). It is the same move the repository already made once (r3 derived from r2 offline), so it adds no new kind of thing. Option (b) is the fallback if the root wants no new modules; option (a) is rejected because it keeps the label-equality verifier as a second authority forever.
