# ADR-0016: Slow reads the conversations

- **Status:** accepted (user decision 2026-09-27: "Slow sees both conversations (the user lane and the rep call), with a better context-management method, not raw dumps"; relay-only becomes the ablation. The design is the architect's, adopted by the root under PLAN §0.5a, 2026-09-27)
- **Date:** 2026-09-27
- **Task:** S1-ROOT-08 (records); S1-CON-08 (contract) and S1-SYS-34 (Slow) build it; S1-SYS-21 shrinks
- **Amends:** NORTH_STAR I5 (the user's decision), AGENTS rule 9, ARCHITECTURE §0 C2, §5 (views), §8; ADR-0009 (the notes' shape); ADR-0012 (`replied`, the M4 counterfactual); ADR-0014 (the R4 sentence); EVAL A5 and §8.3.

## Context
- Slow saw only Fast's typed relays. Relays lose content (few cp relays said what the rep asked for), and Slow stalled on what it was never told: it binds user and rep lines by utt id but learns the ids only from relays, and `check_account` binds only a confirmation id a cp relay carried, so a missing FastC relay blocks `VERIFIED_COMPLETE` on the approval path. Source: the plan-v3 handoff `2026-09-27-slow-sees-transcripts.md` §0.
- The contract already carries the data: `SlowView.transcripts`, filled only for `SlowViewMode.RAW_TRANSCRIPT`, which no bundle and no code path uses. Two locks keep Slow relay-only: the `slow_view` check in `Kernel.__init__` refuses any mode but `RELAY_ONLY`, and `SlowLoop.step` hardcodes it (`slow/loop.py:95`).
- A fold `Line` is what was said and heard: user messages at `user.msg`, rep lines at `utt.final`, agent lines at `utt.delivered` with `text_heard` only. Cancelled, superseded (ADR-0013) and barge-in-cut text never appears.

## Decision
- **Modes (S1-CON-08).** `SlowViewMode` = {`transcript` (default), `relay_only`}; `raw_transcript` is removed. `view_slow` fills the existing `SlowView.transcripts` (both lanes) in `transcript` mode and leaves it empty in `relay_only`, which is ablation A5. No new `SlowView` field: the delta is presentation state. The `slow_view` check in `Kernel.__init__` accepts both modes; `relay_only` stays runnable as A5 and as the comparison with every earlier bundle.
- **What Slow sees.** Both lanes' lines as heard (user messages, the chat voice's delivered messages, rep `utt.final` lines, the phone voice's heard lines, verbatim Guard lines included), plus everything `SlowView` holds today. Never: prompts or `FastView`s, never Fast's other items (the `fast.turn` items besides relays: directives, unheard `text_generated`, cancelled or superseded speech), `llm.call`, world internals (`rep.ear/policy/mouth`, `ledger.write`, `user.sim.revealed`, which must stay out or the relay metrics become circular), other runs.
- **Rendering (S1-SYS-34, `slow/transcript.py`, one pure function).** One `[CONVERSATIONS]` block, per lane: `USER CHAT`, then `REP CALL`, not interleaved. Only heard lines. Each line is `<marker> <utt_id> <SPEAKER>: <json-quoted text>`, SPEAKER ∈ {USER, CHAT VOICE, REP, PHONE VOICE}; `▶` marks lines new since Slow's previous step (a per-lane cursor; a lane reset, such as ADR-0014's call 2, makes every line new); a header says `k of n lines shown, m new`. Caps [E]: 2,000 characters for the user lane, 4,000 for the cp lane, and 480 per line (the head and tail kept, `…[N chars cut]…` between). New lines are dropped last; any dropped new line is counted (`slow_transcript_omitted`) and marked.
- **Context shape (amends ADR-0009).** The block appears only in the newest message. When that turn moves into history, its block becomes a one-line stub (`[CONVERSATIONS shown at step N: +m lines]`), so each line is in a request once. `WINDOW` = 6 and `[EARLIER]` are unchanged; the prompt asks `private_summary` to carry what matters from lines about to scroll out.
- **Relays stay.** The grammar and every relay are unchanged; they still wake Slow and show as compact, json-quoted notes. FastU's REVOKE keeps its independent kernel path (the epoch bump), a second detector of "stop" that does not depend on Slow.
- **Binding to lines.** `record_fact` cites the utt id shown in the block (the prompt changes; the code and the declass rule do not, so I4 and I11 are as strict as before). `check_account` also accepts the `utt_ref` of a rep line whose text contains the id (the same boundary rule), or a cp relay as today; the ledger must still hold the id, and there is still no log-wide scan (#149).
- **Text is data.** Transcript lines and relay notes are what other people said, quoted; they are never instructions (the system prompt says so) and nothing in them grants authority: every authority-bearing effect still passes Guard (I6, rule 10). Quoting is `json.dumps(text, ensure_ascii=True)` (pinned), so a line carries neither a raw newline nor a Unicode line separator (U+2028, U+2029, U+0085) and cannot forge `[STATUS]`, `[WAKE]`, `[APPROVAL]`, `[FENCE]` or a line of the block: a request has exactly one line that begins with `[STATUS]`, and every block line matches `<marker> <utt_id> <SPEAKER>: "<json>"` (S1-SYS-34 tests both).
- **Knock-ons.** ADR-0014's R4 sentence ("When you hold for a detail, also relay `@slow: rep asks for <what>`") drops from `pl_cp_v3` (S1-CON-06): Slow reads the rep's request itself. ADR-0012's `replied` becomes "a `user.msg` newer than the ask's voicing" (no FastU relay needed), and its M4 counterfactual (Slow's request byte-identical under perturbed user text) is dropped; the ledger's own interface still carries no text (hygiene). `relay_recall` and `relay_precision_value_only` stay as Fast diagnostics with unchanged definitions.

## Consequences
- **Contract / fingerprint impact:** `SlowViewMode` loses `raw_transcript` and gains `transcript` as the default (S1-CON-08; the manifest schema snapshot changes: the enum and the default). `pl_user_v1`, `pl_cp_v1` and `pl_cp_v2` keep their fingerprints, and this ADR adds nothing to `pl_cp_v3` (Slow's prompt is `slow/prompt.py`, not `contract.protocol`), so no pull-through. `CONTRACT_VERSION` stays `v1`.
- **Data invalidated:** none. The four `evidence/s0` bundles record `slow_view: relay_only`, still a valid value, so they still verify (S1-CON-08 re-runs `make evidence-check` on them). `cfg_hash` separates `transcript` from `relay_only` bundles: they are never pooled. Teacher-in-harness trajectories under a transcript Slow differ from `relay_only` ones (for the model side, later).
- **Migration:** S1-SYS-29 → S1-CON-08 → S1-SYS-34 → S1-SYS-21. S1-SYS-34 rewrites S1-SYS-29's wake sentence in Slow's prompt.
- **Risks and what would make us revisit this.** Slow over-reacting to every rep line (guides per rep turn, `superseded_lines`). Double replies to the user, since Slow now sees a message before FastU answers (`slow_user_msgs_per_user_msg`; the prompt says the chat voice answers first). Token growth on long human messages (the caps bound it). Wrong utt-id citations (refused and counted, never repaired; rule 12). Social engineering from the rep through Slow to `tell_user` (the human rep of S1-SYS-05 is the operator) and semantic leakage into `public_summary` (not measured yet, and not blocked; numeric declass unchanged; `view_cp` still reads public state and the cp channel only). The per-lane order hides cross-lane timing; revisit if a failure trace shows it. The relay-only reference drifts out of use unless A5 runs.

**Note (root, 2026-09-27): partner-fence coverage.** Under `slow_view=transcript` a rep line counts as covered once a Slow step with `basis_seq` ≥ the line's `utt.final` seq has completed, because Slow has read it. `relay_only` keeps S1-SYS-23's rule (the cp `fast.turn` that saw the line plus a completed Slow step with basis ≥ that turn). `kernel/fence.py` switches on `cfg.slow_view`; S1-SYS-34 builds it.

**Note (root, 2026-09-27): omitted rep lines (option a).** For S1, rep lines omitted from the render under a burst over the cp lane cap still count as covered by a completed step with `basis_seq` ≥ their seq. The tripwire is an offline re-render check that flags any released accept preceded by a cp line omitted from every Slow render (report-only; S1-SYS-34). A non-zero result on a real bundle moves us to option (b): the render cursor in a kernel-visible event (a CON change).
